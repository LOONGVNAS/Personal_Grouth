## CRP工作法 阅读摘要
----

**低效往往不是人不够努力，而是系统出了问题；要先修复系统，再谈效率。**

书中把个人和团队效率问题拆解成三个关键模块：

- **C 沟通**：减少信息内耗，让信息及时、准确地流动，避免反复确认和遗漏。

- **P 规划**：用任务、项目、会议和 OKR 等机制管理时间，把精力集中在最重要、最优先的工作上。

- **R 资源**：把知识、流程和文档沉淀下来，让重复工作可检索、可复用、可自动化。

它强调的不只是“个人时间管理”，而是从“个人高效”升级到“团队高效”。

真正拖垮团队的，常常是沟通断层、任务混乱和信息孤岛；

通过建立可复用、可追踪、可协作的工作系统，让每个人少做低价值重复劳动，从而提升整体产出。

另外，商业和制造管理里也有“CRP”，比如**能力需求计划**或**连续库存补充计划**，但它们和这本书不是同一概念。

## CRP 指导知识库落地
---

用开源系统做企业知识库和解决方案案例库，建议走**“一个可沉淀的知识库 + 一个可检索的 AI 问答层 + 一套知识运营机制”**的架构。

这样既能保证私域知识不外流，也能让知识从“存起来”变成“用得上”。

### **推荐架构**

| 层级       | 作用                             | 开源方案示例                                       |
| :--------- | :------------------------------- | :------------------------------------------------- |
| 知识库     | 文档沉淀、协作编辑、权限管理     | Docmost、Outline、Wiki.js、BookStack、zyplayer-doc |
| AI 问答    | 对内部文档做 RAG 检索问答        | Dify、FastGPT、MaxKB、RAGFlow                      |
| 向量与模型 | 文档切片、向量化、语义检索       | Qdrant/Milvus + Ollama/vLLM + 本地模型             |
| 集成入口   | 让员工在日常系统里直接获取知识   | 飞书/钉钉/企微、GitLab、OA、CRM、工单系统          |
| 运维治理   | 备份、权限、审计、版本、生命周期 | Docker/K8s、LDAP/SSO、日志审计、内容审核           |

### **知识库层**

- **Docmost**：比较像 Confluence/Notion 的开源替代，支持实时协作、富文本+Markdown、图表、空间隔离，适合中大型团队做统一知识库。
- **Outline**：体验现代，适合技术团队，但自托管时需要自行处理认证、备份和权限治理。
- **Wiki.js / BookStack**：更适合结构化文档、制度手册、SOP、运维知识库；BookStack 的“书-章-页”结构对案例库整理很友好。
- **zyplayer-doc**：更偏企业级私有化知识库，支持多级权限、Office 文档、AI 问答、对外发布，适合需要强权限管控的场景。

若团队已经有 **GitLab**，也可以先用 GitLab Wiki 做研发类知识沉淀；

若主要沉淀 Office、PDF、制度文件，则更适合 Docmost、zyplayer-doc、BookStack 这类产品。

### **AI 问答层**

知识库建好后，建议再加一层 RAG 问答，让员工可以直接用自然语言查制度、查案例、查方案。

- **Dify**：开源 LLM 应用平台，RAG 能力成熟，支持工作流、Agent、API 对接，适合有技术团队的企业做深度定制。
- **FastGPT**：上手较快，适合快速搭建内部知识问答系统。
- **MaxKB**：开源企业级智能体平台，适合做内部知识问答、客服助手、业务智能体。
- **RAGFlow**：文档解析能力较强，适合处理 PDF、Word、PPT 等多格式企业文档。

本地模型可以用 **Ollama / vLLM** 跑 Qwen、DeepSeek 等开源模型，向量库可选 **Qdrant、Milvus、pgvector**。

### **解决方案案例库**

案例库不能只当文档仓库，建议按统一模板沉淀：

- **客户背景**：行业、规模、业务痛点。
- **问题描述**：客户遇到的核心问题。
- **解决方案**：技术架构、实施步骤、工具清单。
- **交付成果**：上线效果、指标变化、客户反馈。
- **复用边界**：适用行业、前置条件、风险点。
- **关联知识**：相关产品文档、API、SOP、复盘报告。

可以用标签体系做检索，例如：`行业 / 客户规模 / 技术栈 / 交付周期 / 是否可对外 / 责任人`。

这样后续销售、售前、交付、研发都能快速复用。

### **让私域知识快速流通的关键机制**

- **统一入口**：把知识库和 AI 问答嵌入飞书、钉钉、企微或 OA，减少“找不到知识”的问题。
- **权限分级**：按部门、项目、密级设置可见范围，案例库尤其要区分“内部复用”和“对外可发布”。
- **内容责任人**：每个知识库空间、每个案例都要有 Owner，定期确认内容是否仍然有效。
- **版本管理**：技术方案、产品文档、合同模板都要保留历史版本，避免旧方案误导新项目。
- **搜索优化**：标题、标签、摘要要规范，AI 问答效果很大程度上取决于文档是否结构化。
- **贡献激励**：把案例沉淀纳入项目复盘、售前支持、交付验收流程，而不是只靠个人自觉。

### **一个可落地的起步方案**

若是中小团队，可以先这样搭：

1. **知识库**：Docmost 或 zyplayer-doc，用于沉淀制度、方案、案例、产品文档。
2. **AI 问答**：Dify 或 MaxKB，接入知识库做 RAG 问答。
3. **本地模型**：Ollama 跑 Qwen2.5 或 DeepSeek 系列模型。
4. **向量库**：Qdrant 或 Milvus Lite。
5. **入口**：先接入企微/飞书/钉钉，再逐步对接 CRM、工单、项目管理工具。
6. **运营**：先建“解决方案案例库”“产品知识库”“客户交付库”三个空间，跑通模板和权限。

### **需要注意的坑**

- 不要把“能聊天”当成知识库建成。AI 回答质量取决于文档质量、切片规则和检索效果。
- 开源不等于零成本。部署、备份、权限、模型运维、内容治理都需要持续投入。
- 案例库要区分“可复用知识”和“敏感客户信息”，避免把合同细节、报价、客户隐私直接暴露给全员。
- 迁移旧文档时，优先整理高频使用内容，不要一次性把所有历史文件都灌进去。
